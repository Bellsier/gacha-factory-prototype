# 구현 구조와 통합 안내

이 프로젝트는 빌드 없는 독립 웹 게임입니다. 원본 게임 코드를 병합하거나 기존 저장을 변환하지 않았습니다. Task112 문서는 연결 도구로 참고했으며 기존 일꾼·가챠·경제 엔진의 연동은 별도 작업입니다.

## 파일 역할

| 파일 | 책임 |
| --- | --- |
| `index.html` | Canvas, HUD, 패널, 조작 버튼과 스크립트 로딩 |
| `src/style.css` | 전체 화면 구성과 반응형 패널 |
| `src/data.js` | 저장 키, 자원·지역·연구·레시피, 공통 상수 |
| `src/world.js` | 결정적인 지도·오브젝트·적 생성, 충돌 판정 |
| `src/core.js` | 상태, 이동·전투·채굴·상호작용, 제작·농사·이동 수단, 저장 검증 |
| `src/render.js` | 카메라, 직접 그린 픽셀풍 도형, 효과, 미니맵 |
| `src/app.js` | 키 입력, DOM 패널, localStorage·JSON, 프레임 루프 |
| `tests/` | 규칙 테스트와 Chromium 실제 입력 여정 |
| `tools/` | 단일 HTML·ZIP 패키징 |

스크립트는 `data → world → core → render → app` 순서로 전역 `CG` 네임스페이스를 공유합니다. 외부 게임 라이브러리나 이미지 로딩이 필요하지 않습니다.

## 상태와 시간

`Game.state`에 지역·플레이어·재고·경험·장비·연구·방문·기록·복구 플래그·퍼즐·텔레포터·광맥·농사·장식을 저장합니다. `Game.step`은 최대 시간 간격을 제한하고 패널이 열리면 시뮬레이션을 멈춥니다. 광맥 재생과 농사 성장에는 이 플레이 시간이 적용됩니다.

`makeWorld`는 지역 진입 시 오브젝트와 적을 생성합니다. 적의 현재 체력·위치와 투사체는 영속 상태가 아니므로 재진입·불러오기 때 적이 초기화됩니다. 지역의 복구 플래그는 상태에 보존됩니다. `syncWorld`는 복구한 산맥 터널의 통행 가능 여부를 지역 생성·불러오기와 동기화합니다.

B1에서는 레일 주변의 장식 장애물 생성을 제외합니다. 수레는 기존 트랙의 가로 범위에 제한하며 하차 시 충돌하지 않는 위치를 찾습니다. B4의 일반 기록 상호작용은 연구실 복원이 완료되어야 열립니다. 렌더러는 복구된 터널을 열린 형태로 표현합니다.

## 저장 경계

`chaegulGongbang.experimental.v01`만 사용하며 `gachaFactorySave`와 `gachaFactoryView`는 사용하지 않습니다. `serialize`는 상태를 JSON으로 만들고 `fromSave`는 버전·지역·숫자 등을 검사하고 허용된 항목을 복원합니다. 불러온 좌표가 장애물 안이면 안전한 위치로 옮깁니다.

브라우저 저장 접근과 쓰기 실패는 UI에 알립니다. 손상·미지원 저장을 발견하면 자동 저장을 막고 원본 내보내기를 제공합니다. 사용자가 확인한 JSON 가져오기는 기존 실험판 진행을 교체합니다. 원본 보호 중에는 덮어쓰기 경고를 추가로 표시합니다. 자동 저장은 약 10초 간격이며 P와 상단 버튼으로 수동 저장할 수 있습니다.

## 원본에 통합할 때

먼저 원본의 재고·연구·장비·경험 인터페이스와 실험판의 `Game.state` 사이에 명시적인 어댑터를 설계해야 합니다. 실험판의 재고를 기존 경제 상태에 그대로 덮어쓰지 마세요. 저장 키와 버전·마이그레이션 정책을 별도로 정한 뒤 기존 저장의 복사본으로 검증해야 합니다.

지도 진입·상호작용·제작 요청은 원본 엔진의 검증된 명령에 연결하고 Canvas 렌더러에는 표시할 상태를 제공하는 방식이 가능합니다. 일꾼·가챠·경제를 연동하기 전에는 중복 시간 진행, 자원 중복 지급, 오프라인 진행과 패널 일시정지의 관계를 결정해야 합니다. 임시 마을 배치와 게임 수치는 정식 청사진의 결정으로 간주하지 않습니다.

참고 기준은 PR #34의 `d21fb3437d11b2d78fe552e2760520b3c9cc388b`이며, 전달용 브랜치 기준은 main `e00c62d867d8bd6fdc39434f47ac9504d3696eb5`입니다. 원래 PR #34와 main의 변경은 이 실험판 범위에 포함하지 않습니다.

## 실행·검증·패키징

로컬 HTTP 서버에서 `index.html`을 제공합니다. `npm test`는 규칙 검사, `npm run test:browser`는 실제 Chromium 입력 여정, `npm run package`는 배포물 생성에 사용합니다. 브라우저 테스트에는 Playwright·Chromium과 HTTP 서버가 필요하며 `GAME_URL`로 주소를 지정합니다. 도구와 테스트는 복원된 소스에 포함됩니다.

환경 초기화로 소스가 사라져 대화의 전체 소스와 확인된 수정 사항을 바탕으로 복원했습니다. 일부 공백·서식은 달라졌으며 복원은 바이트 단위 동일성을 보증하지 않습니다. 최종 테스트와 배포물 무결성 결과는 TEST-REPORT.md에 기록합니다. 관리형 Chromium의 `file://` 정책 차단은 호환성 성공으로 기록하지 않습니다.
