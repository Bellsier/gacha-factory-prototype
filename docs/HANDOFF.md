## 3. 실행, 테스트, 빌드

### 실행

```bash
python3 -m http.server 43191 --bind 127.0.0.1
# 브라우저에서 http://127.0.0.1:43191
```

`index.html`을 파일로 바로 열어도 된다(`file://`). 기본 화면은 탑다운이고, 이전 2.5D 화면은 주소 뒤에 `?view=classic`(다시 `?view=topdown`)을 붙인다. 이 선택은 localStorage 키 `gachaFactoryView`에 따로 기억되며 게임 저장과 무관하다.

조작: PC는 WASD·방향키 이동, **E/Space** 상호작용, **T** 횃불, **R** 정원 장식 회수, **Q** 다음 장식 종류, **Esc** 패널 닫기. 휴대폰은 왼쪽 아래 조이스틱, 오른쪽 아래 행동 버튼, 그 위 횃불 버튼과 (정원에서만) 장식 버튼.

## 5. 구조의 핵심 규칙

1. **게임 상태는 기존 로직 파일이 소유한다.** 탑다운 렌더러(`js/topdown/*`)는 `state`, `permanent`, 지형 함수를 **읽기만** 하고, 바꾸는 일은 기존 함수(`secureMine`, `mineMine`, `setPlayerHeld`, `placeTorch` 등)로만 한다.
2. **게임 틱과 그리기를 나눈다.** 경제와 이동은 100ms 틱(`tickLoop`), 그리기는 `requestAnimationFrame`. 플레이어 위치는 두 틱 사이를 보간해 그린다.
3. **렌더러 상태는 저장하지 않는다.** 카메라, 일꾼 걷기 위치(`TD.workerSim`), 빛, 애니메이션, 품질 단계는 모두 `TD`(render.js)에 있고 저장에 들어가지 않는다(테스트로 고정).
4. **충돌은 한 곳에서.** 지형은 `isWorldPointWalkable`(terrain.js), 장애물(광맥, 공방, 제작소, 산 너머의 막히는 풍경)은 `worldObstacles`(player.js)이며, 플레이어(`tickPlayer`)와 일꾼(`tdWorkerWalk`)이 같은 `worldStepFoot`로 움직인다. 이미 겹친 장애물은 막지 않아 기존 저장 위치에서도 걸어 나온다.
5. **일꾼의 생산은 화면과 무관하다.** 생산량은 `autoRate`(systems.js)이며, 일꾼이 걷든 일하든 같다.

## 6. 저장 데이터와 호환

- 저장 키 `gachaFactorySave`(localStorage), 형식 `{ saveVersion: 1, savedAt, permanent, run }`. **saveVersion은 1이다.**
- 새 값은 지금까지처럼 **추가 필드로만** 넣는다. 불러올 때 `sanitize*`가 없는 값은 기본값으로, 잘못된 값은 버리거나 기본값으로 바꾼다. 미래 버전 저장은 덮어쓰지 않는다.
- 탑다운 전환(Task 101~112)에서 추가된 저장 필드는 `run.world.torches`(`[{x, y}]`, 최대 12) 하나뿐이다. 없는 저장은 횃불 없이 불러온다.
- Task 113부터 `run.village`(시작 마을: 시설 부지, 복구 단계, 미감정 유물, 도감, 기증)가 추가 필드로 들어간다. 없는 저장은 "폐허인 마을, 유물 없음"으로 불러온다(청사진 24.8).
- Task 118~121에서 `run.village`에 `district`(광장 기준점 `{x, y, layout}`), `decor`(정원 장식 `[{kind, cell}]`), `specimens`(광물·보석 기증 `[{key, at}]`)가 더해졌다. 없는 저장은 광장을 새로 고르고 빈 정원·표본 없음으로 불러온다. 도로, 집 안 상태, 들고 있는 장식, 박물관 보상은 **저장하지 않는다**(계산하거나 실행 중에만 있음). 이 PR의 저장을 이전 빌드(main)에서 열면 세 필드가 버려진다(정원 장식과 표본 기록이 사라짐, 차감된 자원은 그대로). 되돌아가 여는 것은 지원하지 않는다.
- 저장되는 월드 좌표는 월드 단위(`-10~10`, +y 남쪽)다. 거점·광맥·제작소는 정수, 플레이어·횃불은 실수. 타일·픽셀은 그리기에서만 쓴다.
- 청사진 23.2·23.10: 새 월드(7개 지역)로 옮길 때 기존 터널 상태, 공사, 광맥과 발견·확보 상태, 연구와 지불 내역을 **임의로 초기화·재생성·재과금하지 않는다**. 변환은 별도 마이그레이션 Task로 설계·검증한다.
- 테스트의 저장 구조 검사는 `t103ShapeNow()`(04.js, 고정 저장 + `torches: []` + 기본 `village`, 광장·빈 정원·빈 표본 포함)를 기준으로 한다. 저장 필드를 더하면 이 기준과 Task 103 테스트도 함께 고쳐야 한다(의도한 변경인지 드러나게 하려는 장치다).

## 7. 구현된 기능

자세한 표는 청사진 **24.2**. 요약:

- **경제·제작:** 채굴(수동, 광맥 초당 수입), 공용 저장소, 레시피 18개와 수동·시간·자동 제작, 목표 재고, 제작소(건설 최대 6, 증축 8, 레시피, 업그레이드, 병목 표시), 판매·자동 판매·본사 투자.

- **연구 9개, 납품:** 회사 3곳, 자유 납품, 고정·반복 수주, 명성(최대 36)과 효과, 정기 거래.

## 11. 알려진 문제

- 일꾼끼리는 걸을 때 서로 겹칠 수 있다. 플레이어는 일꾼을 막지 않고 통과한다(갇힘 방지를 위한 선택).
- 공방 옆 등불과 횃불은 길을 막지 않는다(가는 기둥).
- 이전 2.5D 화면(`?view=classic`)에는 횃불, 걷는 일꾼, 마을 건물·광장·정원 그림이 없고 집 안에 들어갈 수 없다(마을 패널로 광장·집·정원·기증·보상은 모두 쓸 수 있다).
- 마을 구역은 현행 월드 안의 **임시 배치**다(청사진 24.9). 생성 월드에 따라 광장이 공방 북쪽·남쪽·동쪽 어디든 놓이고, 정원이 산 쪽에 붙기도 한다.
- 헤드리스 Chromium의 휴대폰 에뮬레이션(3배 해상도)은 프레임당 약 33~37ms라 효과 품질이 자동으로 낮은 단계로 내려간다(구름·반딧불 생략). 실제 휴대폰 기기에서는 시험하지 못했다.
- 청사진 1~22장 일부 구현 서술(산 너머 풍경은 막지 않음, 지도는 왼쪽 위 등)은 지금 코드와 다르다. 24.7에 정리했고 본문은 별도 문서 Task로 고친다.
- `js/ui.js`(1,454줄)에는 2.5D 렌더링과 패널 내용이 함께 있다. 2.5D 제거는 탑다운 동등 테스트를 먼저 갖춘 뒤 별도 Task로 한다(`docs/TOPDOWN_TRANSITION.md` 3.8).

## 12. 처음 작업할 때 조심할 점

- **jsdom과 게임 타이머:** jsdom 창에서 게임을 불러오면 `main.js`의 `setInterval`이 계속 돌아 Node 프로세스가 끝나지 않는다. 직접 스크립트를 쓸 때는 끝에 `process.exit()`를 넣는다. 또 jsdom 안의 `renderAll` 등 DOM 갱신은 느려서, 월드를 많이 만드는 스크립트는 수십 초씩 걸린다.
- **전역 바인딩:** 테스트에서 `win.eval('state = ...')`로 `state`를 바꿔 끼우면 다른 스크립트의 참조가 바뀌지 않는다. 기존 테스트처럼 `state`의 필드를 제자리에서 바꾼다. 전역 함수는 `win.함수 = ...`로 바꿔 끼울 수 있다(Task 68 테스트가 풍경을 끌 때 쓴다).
- **캐시:** `worldScenery()`(풍경 장애물)는 광맥 배열이 바뀔 때만 다시 계산하고, `tdWorkerPlacements()`는 일꾼·광맥·제작소·터널 키로 캐시한다. 상태를 직접 고치는 테스트에서는 이 캐시를 염두에 둔다.
- **마을 구역 캐시:** `villageObstacleBoxes()`(마을 벽·집·장식)와 `villageRoads()`는 캐시한다. 장식은 `villageDecorPlace/Move/Remove`로만 바꾼다(버전 카운터가 캐시를 비움). 테스트에서 `state.village`를 통째로 바꾸면 다른 객체라서 캐시가 알아서 비워진다. `VILLAGE_HOME_SCENE`(집 안)과 `VILLAGE_GARDEN_UI`(고른 종류, 들고 있는 장식)는 페이지 실행 중에만 있는 값이다.
- **마을 부지:** `villageEnsureSites()`가 시작(boot)과 틱에서 부지가 없을 때만 고른다(그다음 `villageEnsureDistrict()`로 광장). 테스트에서 `state`를 새로 채운 뒤 부지가 필요하면 직접 부른다. 부지는 한 번 정하면 저장되며, 문은 부지 점(건물 앞)이다. 문 근처에 광맥이 있으면 가장 가까운 대상이 상호작용 대상이 된다.
- **불러오기 순서:** 스크립트 순서(4장)는 index.html, `tests/chunks/00.js`의 `MODULE_FILES`, `tools/build-dist.js`의 단일 HTML(index.html을 따른다)에 함께 영향을 준다. `tools/simulate.js`는 탑다운 모듈 없이 로직만 불러온다.
- **2.5D 코드:** 아직 지우지 않는다. 2.5D 전용 회귀 테스트가 많고, `?view=classic` 흐름이 회귀 확인에 쓰인다.
