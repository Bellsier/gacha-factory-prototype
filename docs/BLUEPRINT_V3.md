# 채굴 공방 Blueprint v3

> 현재 게임의 최종 디자인 기준선.
> 구현보다 게임 경험을 우선하며, 기존 코드와 충돌할 경우 코드를 청사진에 맞춰 조정한다.
> 본 문서는 2026-09 기준으로 확정된 핵심 방향을 기록한다.

---

## 1. 게임 정체성

채굴 공방은 거점을 중심으로 주변 지역을 개척하고, 광맥에서 자원을 채굴하여 공용 저장소에 모은 뒤, 거점 주변의 제작소에서 상위 자원과 완성품을 만들어 판매하는 간단한 2D 채굴·제작 경영 게임이다.

게임의 목표는 대형 공장을 건설하거나 복잡한 물류 퍼즐을 해결하는 것이 아니다.

핵심은 다음의 작은 선택을 반복하며 장기적으로 공방을 성장시키는 것이다.

- 어떤 지역을 먼저 개발할지 결정
- 어떤 광맥을 확보할지 결정
- 필요한 자원을 채굴
- 공용 자원을 이용해 제작
- 생산 병목과 자원 부족을 개선
- 더 좋은 광맥과 제작품을 향해 거점을 확장

---

## 2. 핵심 플레이 루프

탐색 → 광맥 발견/확보 → 채굴 → 공용 저장소 → 제작소 → 상위 자원/완성품 → 판매 → 성장 → 지역 확장 → 더 좋은 광맥

게임이 진행될수록 새로운 자원, 제작법, 제작소, 지역, 자동화가 추가되어 같은 기본 루프의 선택지가 넓어진다.

---

## 3. 월드와 2D 표현

게임 화면은 2D 표현을 기본으로 한다. 필요하다면 이후 시각적 깊이 표현을 추가할 수 있지만, 게임 시스템은 특정 렌더링 방식에 종속되지 않는다.

월드는 다음 구조를 가진다.

- 거점이 중심에 존재한다.
- 거점 주변에 개발 가능한 지역이 존재한다.
- 플레이어는 거점에서 바깥쪽으로 지역을 확장한다.
- 광맥은 월드에 미리 존재한다.
- 광맥의 위치와 등급은 지역에 따라 달라진다.
- 실제 지형과 시각적 배치는 2D 표현에 맞춰 설계한다.

### 중요한 원칙

공장 전체를 하나의 거대한 자유 배치 Grid로 만드는 것이 아니다.

월드 확장과 광맥 확보가 공간 설계의 중심이다.

---

## 4. 거점

거점은 플레이어의 운영 중심이다.

거점에서 다음 기능을 수행한다.

- 공용 자원 관리
- 제작소 건설 및 운영
- 연구
- 시설 업그레이드
- 자동화 관리
- 지역 확장
- 판매 및 경제 활동

거점은 게임 시작 시 작게 시작하며, 진행에 따라 기능과 주변 개발 범위를 확장한다.

---

## 5. 지역 확장

지역은 거점과의 거리 및 지역 특성에 따라 자원 접근성이 달라진다.

기본 진행 방향:

거점 인접 지역 → 중거리 지역 → 원거리 지역 → 외곽 지역

일반적으로 바깥쪽으로 갈수록 더 높은 등급의 광맥을 얻을 가능성이 커진다.

최고급 광맥은 제한적으로 배치할 수 있다.

지역 확장은 단순한 맵 확장이 아니라 새로운 자원과 제작 가능성을 여는 성장 요소다.

---

## 6. 광맥과 채굴

광맥은 플레이어가 직접 생성하는 건물이 아니라 월드에 존재하는 자원 공급원이다.

각 광맥은 최소한 다음 정보를 가진다.

- id
- 위치
- 자원 종류
- 등급
- 채굴 관련 수치
- 개발/확보 상태

각 광맥은 독립적인 채굴 대상으로 취급한다.

채굴된 자원은 생산라인별 별도 재고가 아니라 거점의 공용 저장소로 들어간다.

예:

철 광맥 → 철광석 → 공용 저장소

구리 광맥 → 구리광석 → 공용 저장소

Worker와 자동화는 채굴 시스템을 보조할 수 있지만, Worker 자체가 게임의 주 성장축이 되지는 않는다.

---

## 7. 공용 저장소

채굴된 기본 자원과 제작에 필요한 자원은 거점의 공용 저장소에서 관리한다.

예:

- 철광석: 1,240
- 구리광석: 820
- 석탄: 530

기본 설계에서는 여러 저장소가 서로 다른 생산라인의 재고를 따로 가지는 구조를 핵심으로 삼지 않는다.

공용 저장소가 기본 자원 풀이다.

제작소는 공용 저장소의 자원을 소비하여 제작한다.

이 구조를 통해 플레이어가 Belt 연결이나 물류 경로를 직접 관리하지 않아도 생산 시스템을 이해하고 운영할 수 있도록 한다.

---

## 8. 제작소

제작소는 거점 주변의 건설 가능한 공간에 설치하는 생산 시설이다.

제작소는 공용 저장소에서 필요한 자원을 소비하고 상위 자원 또는 완성품을 생산한다.

예:

철광석 ×2 + 석탄 ×1 → 철괴 ×1

철괴 ×3 + 구리괴 ×1 → 기계 부품 ×1

기계 부품 ×3 + 희귀 광물 ×2 → 고급 채굴 장비 ×1

제작은 여러 단계로 확장될 수 있다.

원자재 → 1차 가공품 → 중간재 → 상위재 → 완성품

하나의 중간재가 여러 제작품의 재료로 사용될 수 있다.

---

## 9. 생산과 소비

개별 아이템의 실제 이동을 시뮬레이션하지 않는다.

관리하는 핵심 값은 수치 기반이다.

- 생산량
- 소비량
- 재고
- 생산 주기
- 처리량
- 제작 완료량
- 병목 상태

화면에서 필요한 아이템 이동이나 생산 동작은 시각적 표현 또는 애니메이션으로만 표현할 수 있다.

---

## 10. 병목과 효율

플레이어가 생산 시스템을 개선할 수 있도록 생산 병목을 관찰할 수 있어야 한다.

예:

- 광맥 생산량 < 제작소 소비량
- 제작소 처리량 < 필요한 생산량
- 특정 자원 부족
- 특정 제작품 과잉 생산

플레이어는 상황에 따라 다음을 선택한다.

- 새로운 광맥 확보
- 기존 광맥 강화
- 제작소 추가
- 제작소 업그레이드
- 더 좋은 지역으로 확장
- 자동화

복잡성을 물류 퍼즐에서 만드는 것이 아니라 자원과 제작 조합, 병목 관리에서 만든다.

---

## 11. 연구

연구는 새로운 가능성을 해금한다.

예:

- 새로운 자원
- 새로운 레시피
- 새로운 제작소
- 새로운 지역
- 새로운 자동화
- 새로운 운영 기능

연구는 기존 생산량을 단순히 높이는 기능과 구분한다.

---

## 12. 시설 업그레이드

시설 업그레이드는 생산 능력과 운영 효율을 높이는 역할을 한다.

예:

- 제작 속도 증가
- 생산량 증가
- 시설 처리 능력 증가
- 저장 능력 증가
- 채굴 효율 증가

연구와 시설 업그레이드는 역할을 분리한다.

연구 = 무엇을 할 수 있는가

업그레이드 = 얼마나 효율적으로 할 수 있는가

---

## 13. 자동화

자동화는 플레이어의 반복적인 직접 조작을 줄인다.

예:

- 자동 채굴
- 자동 제작
- 자동 판매
- 자동 운영

자동화는 단순히 수치를 올리는 것보다 플레이어가 직접 관리해야 하는 횟수를 줄이는 것을 우선한다.

초반에는 직접 조작이 필요하고, 진행할수록 자동화 비중이 높아지는 방향을 사용한다.

---

## 14. Worker

Worker는 핵심 생산라인의 보조 시스템이다.

가능한 역할:

- 채굴
- 제작 보조
- 운영
- 기타 자동화 보조

Worker를 RPG식 성장의 중심으로 만들지 않는다.

기존 Worker Gacha 구현은 현재 프로토타입의 자산으로 보존할 수 있으며, 향후 플레이어에게 보여주는 개념은 필요에 따라 채용/배치 중심으로 단순화할 수 있다.

Worker가 강해지는 것 자체보다 거점과 생산 시스템이 성장하는 것을 장기 성장의 중심으로 한다.

---

## 15. 경제

기본 경제 루프:

자원 채굴 → 제작 → 완성품 판매 → 골드 → 시설/연구/확장 → 더 좋은 생산

판매는 최종 목표가 아니라 다음 단계의 성장에 필요한 수단이다.

기존 골드, 제품, 프레스티지 등의 시스템은 이 루프에 맞춰 유지하거나 조정한다.

---

## 16. 장기 플레이 구조

게임의 장기 플레이는 콘텐츠를 무작정 크게 만드는 방식으로 확보하지 않는다.

다음 네 가지를 조합한다.

### 자원

더 좋은 광맥과 새로운 자원.

### 제작

더 높은 단계의 재료와 완성품.

### 효율

생산량, 소비량, 병목, 업그레이드.

### 확장

거점에서 더 먼 지역으로 진출.

따라서 게임은 다음 순환을 가진다.

더 좋은 광맥 → 더 좋은 제작품 → 더 높은 판매 가치 → 더 넓은 개발 범위 → 다시 더 좋은 광맥

---

## 17. 스토리

스토리는 핵심 시스템에 포함하지 않는다.

필수 스토리 진행, 챕터, 컷신, 복잡한 NPC 관계를 요구하지 않는다.

필요하다면 향후 다음 정도의 가벼운 세계관 표현만 추가할 수 있다.

- 짧은 NPC 대사
- 지역 설명
- 광맥 설명
- 간단한 시작 문구
- 환경을 통한 배경 표현

플레이어가 게임을 계속 진행하기 위해 스토리를 따라가야 하는 구조는 만들지 않는다.

게임 자체의 탐험, 채굴, 제작, 확장이 플레이 동력이다.

---

## 18. 의도적으로 만들지 않는 시스템

다음 요소는 현재 핵심 시스템으로 만들지 않는다.

- 대형 공장형 자유 건설
- 복잡한 Belt 물류 퍼즐
- 개별 아이템 물리
- 아이템 충돌
- 복잡한 Belt 경로 탐색
- Splitter 비율 최적화
- Merger 물류 퍼즐
- 대규모 물류 네트워크
- 과도한 Worker 이동 AI
- 복잡한 생산 비율 시뮬레이션
- 스토리 중심 진행
- Worker RPG 중심 성장

Belt, Splitter, Merger 등의 시스템은 필요성이 명확해지는 경우에만 별도의 설계 과정을 거쳐 추가한다.

---

## 19. 현재 코드와의 관계

기존 Task 21~26에서 만든 기반은 폐기하지 않는다.

재사용을 우선 검토하는 대상:

- state / permanent 저장 구조
- resources
- products
- gold
- characters
- facility
- workforce
- Worker ID
- Factory Node 기본 데이터와 검증
- Factory Link 기본 데이터와 검증
- 저장/로드 및 saveVersion
- 모듈 분리 구조
- 기존 테스트 구조

변경 가능성이 높은 대상:

- 25×25 고정 Factory Grid
- Factory Node의 현재 production/storage 의미
- Factory Link를 생산라인의 핵심 연결로 사용할지 여부
- 개별 Storage 중심 구조
- 기존 site 해금 구조
- 기존 UI의 공장 표현

이 항목들은 기존 코드를 즉시 삭제하거나 임의로 변경하지 않는다.

현재 코드와 Blueprint의 차이를 확인한 뒤 별도의 구현/마이그레이션 Task로 처리한다.

---

## 20. 구현 원칙

### 작은 Task

하나의 의미 있는 기능을 10~30분 정도의 Task로 나눈다.

### 한 번에 하나

동시에 여러 시스템을 건드리지 않는다.

### 구현 후 검증

Task 완료 조건:

코드 변경 → 테스트 → 실행 확인 → 커밋 → GitHub 확인

### 설계와 구현 분리

Blueprint와 충돌하는 기존 코드가 발견되면 기존 코드를 기준으로 설계를 왜곡하지 않는다.

먼저 차이를 기록하고 필요한 변경을 별도 Task로 만든다.

### 과도한 시스템 금지

새 기능을 추가할 때 반드시 질문한다.

> 이 기능이 채굴 → 저장 → 제작 → 판매 → 확장이라는 핵심 루프를 실제로 강화하는가?

강화하지 않는다면 현재 범위에서는 추가하지 않는다.

---

## 21. 확장 후보

다음은 가능성만 열어두며 현재 확정 기능이 아니다.

- 고급 지역/섹터
- 더 다양한 광맥
- 더 깊은 제작 단계
- 고급 자동화
- 제작소 특화
- 생산 분석 UI
- 추가 거점 기능
- 간단한 NPC/세계관 요소
- Blueprint 복사/저장 같은 편의 기능

각 항목은 필요성이 생겼을 때 별도의 설계와 Task를 거쳐 확정한다.

---

# 문서화 원칙

이 문서는 현재 채굴 공방의 최종 디자인 기준선이다.

구현 중 기존 코드와 충돌할 경우:

1. 실제 현재 코드를 확인한다.
2. Blueprint와의 차이를 기록한다.
3. 변경이 필요한 범위를 별도 Task로 분리한다.
4. 해당 Task에서 코드를 변경한다.
5. 테스트와 실행 검증 후 다음 Task로 넘어간다.

Blueprint를 구현 편의 때문에 임의로 낮추거나 변경하지 않는다.

반대로 게임의 실제 방향이 다시 바뀌는 경우에는 코드보다 Blueprint를 먼저 갱신한 뒤 다음 구현 Task를 시작한다.
