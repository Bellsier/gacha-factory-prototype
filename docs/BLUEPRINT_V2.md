# 공장 청사진

## 1. 핵심 성장 방향

게임의 핵심 성장은 생산라인을 늘리고 조직하는 것이다.

핵심 루프:

생산라인 증가
→ 공장 복잡도 증가
→ 병목 발생
→ 생산라인 정리 및 재배치
→ 자동화
→ 효율 상승
→ 새로운 생산라인 해금
→ 더 큰 생산 복잡도

공장 시스템의 중심은 개별 일꾼의 성장이나 단순 자원 수집이 아니라
"생산라인을 어떻게 구성하고 확장하는가"에 둔다.

---

## 2. 생산라인 구조

생산라인은 여러 광물과 중간재가 여러 단계의 생산 과정을 거쳐 최종 제품으로 연결되는 구조를 가진다.

기본적인 형태:

광물
→ 1차 가공
→ 중간재
→ 분기/합류
→ 추가 가공
→ 완제품

하나의 중간재가 여러 생산라인에서 재사용될 수 있다.

생산라인의 최소 개념 단위는:

Node + Link

이다.

Node는 생산 또는 물류 기능을 담당하고,
Link는 Node 사이의 연결을 담당한다.

---

## 3. 공장 공간

공장은 Grid 기반 공간으로 설계한다.

기본 공장 영역은 25×25 Grid를 기준으로 한다.

시설 크기는 최대 3×3을 넘지 않는다.

시설은 필요에 따라 1×1, 2×2, 3×3 크기를 사용할 수 있다.

Belt는 1×1 Grid를 차지한다.

실제 맵의 지형, 토지 배치, 광산 위치 등은 향후 배경 지형 디자인에 따라 결정한다.

---

## 4. 공장 구성 요소

초기 공장 시스템의 주요 구성 요소:

### Production Node
자원 또는 중간재를 입력받아 생산물을 출력한다.

### Storage
생산물이나 자원을 저장한다.

Storage는 기본적으로 독립적인 재고를 가진다.
모든 Storage가 하나의 글로벌 재고를 공유하는 구조로 만들지 않는다.

### Belt
Node와 Node를 연결하는 공간적 Link다.

Belt는 실제 아이템 객체를 운반하지 않는다.

### Splitter
하나의 Belt 흐름을 여러 생산라인으로 분기한다.

초기에는 복잡한 비율 설정 없이 자동적인 수요 기반 분배를 기본으로 한다.

향후 연구를 통해 우선순위 분배, 균등 분배, 비율 분배 등의 기능을 추가할 가능성은 있다.

### Merger
여러 Belt 흐름을 하나로 합친다.

Splitter와 Merger는 독립적인 대형 건물이 아니라
Belt에 부착되는 물류 모듈로 취급한다.

Belt를 설치하는 것과 유사한 방식으로 공간에 설치할 수 있다.

---

## 5. Belt와 아이템 처리

실제 개별 아이템의 이동을 시뮬레이션하지 않는다.

즉 다음과 같은 시스템은 만들지 않는다.

- 개별 광석 객체 생성
- 개별 아이템의 Belt 이동
- 아이템별 충돌 판정
- 아이템별 물리 시뮬레이션
- 복잡한 경로 탐색

대신 생산량과 소비량을 수치로 계산한다.

관리해야 할 핵심 데이터:

- 생산량
- 소비량
- 재고
- 처리량
- 생산 주기
- 병목 상태

화면에서 보이는 Belt 위의 아이템 이동은 필요할 경우 시각적인 애니메이션으로만 표현할 수 있다.

---

## 6. Belt 교차

Belt의 교차는 허용한다.

두 Belt가 교차하더라도 서로의 생산량이나 처리량에 영향을 주지 않는다.

교차 지점에서 물류가 막히거나 충돌하는 시스템은 사용하지 않는다.

목표는 물류 퍼즐 자체를 어렵게 만드는 것이 아니라
플레이어가 생산라인의 배치와 조직에 집중하도록 하는 것이다.

---

## 7. 병목과 분석

공장은 생산량, 소비량, 재고, 처리량을 기반으로 병목을 분석할 수 있어야 한다.

향후 분석 UI에서 다음과 같은 정보를 제공할 수 있다.

- 생산량
- 소비량
- 재고
- 처리량
- 병목 Node
- 생산라인별 효율
- 자원 부족
- 과잉 생산

분석 기능은 공장을 단순히 배치하는 게임이 아니라
"배치한 생산라인을 관찰하고 개선하는 게임"으로 만드는 것을 목표로 한다.

---

## 8. 연구 / 시설 / 자동화의 역할 분리

세 시스템의 역할을 명확하게 분리한다.

### 연구
새로운 가능성을 해금한다.

예:
- 새로운 생산법
- 새로운 생산시설
- 새로운 물류 기능
- 새로운 자동화 기능

### 시설 업그레이드
생산라인의 처리 능력을 높인다.

예:
- 생산 속도 증가
- 생산 용량 증가
- 저장 용량 증가

### 자동화
플레이어의 직접적인 개입을 줄인다.

예:
- 자동 생산
- 자동 운송
- 자동 판매
- 자동 분배

연구가 "무엇을 할 수 있는가",
시설이 "얼마나 많이 할 수 있는가",
자동화가 "얼마나 적게 직접 조작해도 되는가"
를 담당하도록 한다.

---

## 9. 인력

Worker는 생산라인 자체보다 보조적인 시스템으로 취급한다.

Worker의 역할은 몇 가지 명확한 역할로 단순화한다.

예상 역할:

- 채굴
- 운송/물류
- 기계 조작
- 관리/기술

Worker를 RPG식 캐릭터 성장의 중심으로 만들지 않는다.

기존 Worker Gacha 시스템의 내부 구현은 향후 재사용할 수 있지만,
플레이어가 보는 개념은 "가챠"보다는 "채용 공고 → 지원자 → 검토 → 채용 → 배치"에 가깝게 변경하는 방향을 고려한다.

---

## 10. 토지와 광산

토지는 단순한 빈 공간이 아니다.

토지 = 건설 공간 + 기본 채굴장

각 토지는 건설 가능한 공간과 기본 채굴장을 가진다.

토지의 광물 등급은 본거지와의 위치 및 주변 지형에 따라 결정한다.

기본적인 진행 방향:

본거지 인접 지역
→ 저급 광물

그 다음 권역
→ 중급 광물

그 다음 권역
→ 고급 광물

외곽의 제한된 지역
→ 최고급 광물

고급 광산은 여러 곳을 배치할 수 있지만,
최고급 광산은 제한적으로 배치한다.

단, 실제 토지 배치와 광산 위치는 아직 확정하지 않는다.

산을 끼고 있는 평야인지,
계곡인지,
분지인지,
기타 지형인지에 따라 최종적인 자원 분포와 토지 구조를 결정한다.

따라서 현재 청사진에서는
"토지 위치와 지형이 자원 등급에 영향을 준다"
까지만 확정한다.

---

## 11. 공간 설계 원칙

공장 공간은 생산라인을 확장하고 정리하는 것이 핵심이다.

따라서 다음을 피한다.

- 복잡한 Belt 물리 시뮬레이션
- 개별 아이템 물리
- 과도한 경로 탐색
- Worker 충돌 및 복잡한 이동 AI
- 복잡한 생산 비율 계산
- 물류 자체를 목적으로 하는 과도한 퍼즐 요소

대신 다음을 강조한다.

- 생산라인 배치
- 공간 활용
- 생산라인 간 연결
- 병목 발견
- 재배치
- 자동화
- 생산라인 확장

---

## 12. 향후 확장 후보

아래 시스템은 현재 확정 구현 대상이 아니라 향후 후보로 둔다.

- Blueprint 복사/붙여넣기
- 생산라인 분석 UI
- 고급 Splitter 기능
- 물류 네트워크
- 연결형 Warehouse
- 토지 확장
- Sector 시스템
- 더 복잡한 생산라인
- 고급 자동화

이 항목들은 향후 별도의 설계 과정을 거친 뒤 확정한다.

---

# 문서화 원칙

이 문서는 현재 공장 시스템의 "디자인 기준선"이다.

따라서 향후 구현 작업에서 기존 코드와 충돌할 경우,
기존 코드에 맞춰 청사진을 임의로 변경하지 않는다.

충돌이 발견되면:
1. 현재 코드의 실제 상태를 확인한다.
2. 청사진과의 차이를 기록한다.
3. 별도의 구현/마이그레이션 작업으로 분리한다.
4. 승인 없이 청사진 자체를 변경하지 않는다.
