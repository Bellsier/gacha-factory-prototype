## 0. 현재 상태와 청사진과의 관계 (2026-10-16)

### 0.1 이 문서의 구현값은 프로토타입 값이다

- 탑다운 렌더러, 카메라, 걷기 애니메이션, 조이스틱, 근접 상호작용, 충돌, 조명, 일꾼 표시·걷기, 횃불은 **구현되어 있다**(Task 104~112, 4장).
- 모두 **현행 프로토타입 월드**(단일 소형 월드 `-10~10`, 서쪽 산맥·터널·산 너머) 위의 구현이다. 청사진 23.2는 이 월드를 최종 지리가 아닌 현행 프로토타입으로 분류하고, 지상 7개 지역의 넓은 월드를 최종 목표로 둔다.
- 여기서 정한 값 — 월드 1단위 = 16px 타일 4개, 정수 확대(화면 짧은 쪽에 약 4단위), 캐릭터 추적 카메라와 경계 정지, 충돌 상자 크기, 조명 수치 — 은 이 프로토타입을 위한 **구현값**이다. 청사진 23.1·23.2·23.10이 미확정으로 둔 최종 규격(카메라, 타일·스프라이트 규격, 대형 월드·청크, 좌표·세이브 이행)을 정하지 않는다. 새 월드로 옮길 때 다시 정한다.
- 저장: saveVersion 1. 탑다운 전환으로 추가된 저장 필드는 `state.world.torches` 하나다(Task 112). 렌더러 상태(카메라, 일꾼 걷기, 빛, 애니메이션)는 저장하지 않는다.

### 0.2 구현의 기준이 된 화면 목표 (2026-10-15 개발 지시, PR #34의 이전 청사진 3.0)

청사진 main 통합본에는 들어 있지 않아 여기에 보존한다. 23.1(탑다운 픽셀 아트)과 충돌하지 않으며, 세부 규격은 위 0.1처럼 프로토타입 값이다.

**화면 목표**
- 게임 화면의 대부분을 월드가 차지한다. 웹페이지처럼 보이는 카드와 목록이 화면의 중심이 되지 않는다.
- 카메라는 캐릭터를 중심으로 따라간다. 월드 가장자리에서는 경계 밖을 비추지 않도록 멈춘다.
- 지형, 벽(산), 광석, 건물, 나무를 정수 배율의 픽셀아트로 그린다. 확대할 때 흐려지지 않게(최근접 보간) 그린다.
- 캐릭터는 네 방향의 걷기와 서 있기 애니메이션을 가진다.
- 지형과 장애물에 부딪히면 멈추거나 벽을 따라 미끄러진다. (청사진 3.1의 충돌 원칙과 같다)
- 광맥, 공방, 마을 시설은 가까이 가서 상호작용한다. 가까이 가면 표시가 뜨고, 키(PC) 또는 버튼(모바일)으로 행동한다.
- 횃불과 조명, 낮은 채도의 환경색으로 아늑한 분위기를 만든다. 조명은 보기 효과이며 게임 수치에 영향을 주지 않는다.
- 조작: PC는 WASD와 방향키 이동, 상호작용 키. 모바일은 화면 위 가상 조이스틱과 상호작용 버튼. 같은 게임을 두 환경에서 할 수 있어야 한다.

**정보 패널.** 연구, 납품, 일꾼 관리, 창고, 제작 목록처럼 정보가 많은 화면은 월드 위에 여닫는 패널로 둔다. 패널은 월드를 가리는 시간을 짧게 하며, 평소에는 월드와 작은 HUD만 보인다.

**시스템과 표현의 분리.** 게임 시스템(좌표, 이동, 충돌, 광맥, 경제, 저장)은 화면 표현 방식에 종속되지 않는다. 탑다운 렌더러는 게임 상태를 읽어 그리기만 하고, 상태를 바꾸는 일은 지금과 같은 게임 함수를 통해서만 한다. 그래서 그래픽을 바꿔도 저장 데이터와 진행은 그대로다.

**월드 좌표와 타일.** 저장되는 월드 좌표(월드 단위, 현재 -10 ~ 10)는 바꾸지 않는다. 탑다운 화면의 타일은 월드 단위를 더 잘게 나눈 그리기 단위이며, 월드 단위 하나가 여러 타일로 그려진다. 구체적인 배율은 전환 설계 문서에서 정한다. 월드 범위를 넓히는 일은 저장 호환을 지키는 별도 결정으로 다룬다.

**이전 표현.** 2.5D 고정 시점(비스듬한 원근 투영, 고정 카메라, Task 61)은 현재 코드에 구현되어 있으며, 탑다운 렌더러가 완성될 때까지 유지한다. 교체는 단계적으로 하고, 단계마다 실행 가능한 상태를 유지한다. (4장)

### 1.2 좌표계

- **월드 단위.** 모든 위치는 월드 단위로 저장된다. 경계는 `BALANCE.world.BOUNDS_*` = -10 ~ 10(21×21). +y가 남쪽(화면 아래), +x가 동쪽.
- **정수 좌표:** 거점, 광맥, 제작소. 광맥 하나가 한 칸을 차지한다는 의미의 "점"이며 크기(발자국)는 없다.
- **실수 좌표:** 플레이어(`state.world.player.x/y`), 산 너머 풍경(고정 해시로 매번 같은 위치, 저장 안 함).
- **지형**(`WORLD_TERRAIN`): 산맥 동쪽 면이 y 구간별 x = -3.5 ~ -4.5, 산 두께 2.6, 터널은 y = 1 ± 0.8, 깊이 1. 모두 0.1 단위 이하의 실수.

### 1.3 현재 렌더링 (2.5D, Task 61)

- `worldToStagePercent(x, y)`: 월드 좌표를 무대(`#worldStage`) 안의 퍼센트 위치와 원근 배율로 바꾼다. 먼 줄(y = -10)은 위쪽에 좁게, 가까운 줄은 아래에 넓게.
- 그리는 것: 지면과 격자(SVG), 산 봉우리·터널(div), 광맥·거점·제작소·플레이어(div, CSS 배경), 산 너머 풍경(div), 탐험 지도(SVG), 선택 정보 상자.
- 언제 그리나: 지형·오브젝트는 `renderAll()`과 구조 변경 때 전체를 다시 만든다. 매 틱(100ms)에는 플레이어 위치(`updatePlayerSprite`)와 지도 점만 옮긴다.
- 그리기와 게임 틱이 같은 100ms 주기라서 움직임이 초당 10번 끊어진다(보간 없음).
- 카메라: 없음(월드 전체가 무대 하나에 고정).

### 1.4 플레이어 이동과 충돌

- 키 입력: `ui.js`의 `onPlayerKey` → `player.js`의 `playerHeld`(저장 안 함). Task 95, 99에서 입력칸·체크박스 포커스 문제를 고쳤다.
- 이동: `tickPlayer()`가 틱마다 `PLAYER_SPEED`(3 월드 단위/초) / 10만큼 움직인다. 대각선은 정규화.
- 충돌: `isWorldPointWalkable(x, y)` 하나로 판정. X와 Y를 따로 풀고(`terrainAdvance`, 이분 탐색), 벽에 붙어 미끄러진다. 막는 것은 **산맥과 월드 경계뿐**이며 광맥, 거점, 제작소는 통과한다. 이미 바위 안에 있으면 막지 않아 빠져나올 수 있다.
- 플레이어 크기: 판정은 점 하나, 바위와 `PLAYER_MARGIN`(0.3)만큼 거리를 둔다.

### 1.5 광맥 표시와 상호작용

- 발견: 플레이어가 `discoveryRadius()`(2.5, 탐사 장비 4.0) 안에 들어오면 `tickExploration()`이 발견 처리.
- 확보·채굴: **거리와 상관없이** 채굴 탭의 버튼으로 한다. 월드의 광맥을 클릭하면 선택과 정보 상자만 뜬다.
- 미발견 광맥은 "?" 바위로 그리고 자원은 숨긴다. 지도에는 나오지 않는다.

## 2. 저장 데이터에 영향을 줄 수 있는 부분

저장 형식은 `{ saveVersion: 1, savedAt, permanent, run }`이고, 월드 관련 저장 값은 `run.world` 아래에 있다.

| 저장 값 | 탑다운 전환에서의 위험 | 원칙 |
|---|---|---|
| `world.player.x/y` (실수, 월드 단위) | 단위를 타일이나 픽셀로 바꾸면 기존 위치가 틀어진다 | **월드 단위 유지.** 타일·픽셀은 그리기에서만 쓴다 |
| `world.player.facing` (up/down/left/right) | 8방향 등으로 늘리면 구 버전이 못 읽는다 | 4방향 유지. 애니메이션 프레임은 저장하지 않는다 |
| `world.player.pose` | 새 자세 값을 저장하면 구 버전이 버린다(불러올 때 idle로 정규화) | 저장 값은 그대로, 걷기 프레임은 렌더러 상태 |
| `world.base`, `mines[].x/y`, `workshops[].x/y` (정수) | 좌표 의미를 "타일 칸"으로 바꾸면 배치가 달라진다 | 정수 월드 좌표 유지 |
| `world.hiddenMineIds`, `tunnelUnlocked`, `tunnelContract` | 영향 없음 | 그대로 |
| 지형(`WORLD_TERRAIN`, 저장 안 함) | 산의 면을 옮기면 저장된 플레이어가 바위 안이 될 수 있다. 그러면 불러올 때 거점으로 옮겨진다 | 지형 데이터를 바꾸지 않는다. 바꿔야 하면 별도 Task에서 영향 검사 |
| `BOUNDS_*` (저장 안 함) | 줄이면 저장 좌표가 경계 밖이 되어 0이나 거점으로 바뀐다 | 줄이지 않는다. 넓히는 것은 기존 좌표를 유지하므로 가능하지만 별도 결정(청사진 23.2, 24.6 #7) |
| `WORLD_MINE_SEEDS` (거점 기준 오프셋) | 바꾸면 이후 지역 해금 광맥 위치가 바뀐다 | 그대로 |
| 새 렌더러 설정(확대, 렌더러 선택) | 저장 데이터에 넣으면 형식이 바뀐다 | 저장에 넣지 않는다. 필요하면 별도 localStorage 키 |
| 앞으로 장애물 충돌 추가 | 저장된 플레이어가 새 장애물 안에 있을 수 있다 | "이미 안에 있으면 막지 않는다" 규칙을 장애물에도 적용 |

결론: **탑다운 전환은 저장 데이터를 바꿀 필요가 없다.** saveVersion은 1로 유지하며, 새 값이 필요하면 지금까지처럼 추가 필드로만 넣는다.

구현 결과(Task 112까지): 기존 저장 값은 그대로이고, 추가 필드는 `world.torches`(플레이어가 놓은 횃불 `[{x, y}]`, 없거나 잘못되면 `[]`, 최대 12개) 하나다. 장애물 충돌(Task 107, 111)에는 "이미 안에 있으면 막지 않는다" 규칙을 적용했다.

## 3. 전환 설계

### 3.1 원칙

1. 게임 상태는 지금 코드가 계속 소유한다. 렌더러는 `state`, `permanent`, 지형 함수를 **읽기만** 한다.
2. 상태를 바꾸는 행동(확보, 채굴, 제작, 이동)은 지금 함수(`secureMine`, `mineMine`, `setPlayerHeld` 등)를 그대로 부른다.
3. 게임 틱(100ms, 경제·이동)과 그리기(`requestAnimationFrame`, 화면 주사율)를 분리한다. 그리기는 직전 두 틱의 플레이어 위치를 보간해 부드럽게 움직인다. 보간용 이전 위치는 렌더러가 들고 있고 저장하지 않는다.
4. 2.5D 렌더러는 탑다운 렌더러가 같은 기능을 갖출 때까지 남긴다. 교체 중 어느 단계에서도 게임을 실행할 수 있어야 한다.
5. 그림은 직접 만든다. 다른 게임의 에셋을 쓰지 않는다.

### 3.2 새 모듈

**jsdom 제약.** `npm test`가 쓰는 jsdom에는 2D 캔버스가 없다(`getContext('2d')`가 `null`). 그래서 렌더러는 컨텍스트가 없으면 그리기만 건너뛰고, 좌표 계산과 그릴 목록은 캔버스 없이 만들 수 있게 나눈다. 실제 그림은 Playwright(Chromium)로 화면을 열어 확인한다.

### 3.3 타일과 화면 배율

- 월드 단위 1 = **4타일**, 타일 1 = **16픽셀**(1배). 월드 21×21 단위 = 84×84 타일.
- 화면 확대는 정수 배율만 쓴다(픽셀이 흐려지지 않게). 화면 가로에 월드 약 8~12 단위가 보이도록 배율을 고른다. 예: PC 1280px 폭 → 2배(가로 약 10단위), 휴대폰 390px 폭 → 2배(가로 약 3단위)는 너무 좁으므로 휴대폰은 1배 또는 타일 크기 조정. 구체 값은 Task 104에서 실제 화면을 보고 정한다.
- 지금 이동 속도 3단위/초 = 12타일/초. 탑다운에서 빠르게 느껴지면 `PLAYER_SPEED`를 조정한다. 이 값은 저장되지 않으므로 저장 호환에 영향이 없지만 밸런스(발견 속도)가 바뀌므로 별도 Task에서 다룬다.
- 산 너머 풍경과 지형은 이미 0.1 단위 이하로 정의되어 타일 4개/단위에서도 모양이 유지된다.
- **구현(Task 104):** 화면 짧은 쪽에 약 4단위가 보이는 정수 배율(PC 1280×800 → 3배, 휴대폰 → 2배, 최대 4배). 이동 속도는 바꾸지 않았다(3단위/초). 이 값들은 프로토타입 구현값이다(0.1).

### 3.4 카메라

- 카메라 중심 = 보간된 플레이어 위치. 화면에 월드 경계 밖이 보이면 그 축은 경계에서 멈춘다.
- 카메라 위치는 렌더러 상태이며 저장하지 않는다.
- 미니맵(탐험 지도, 3.5)은 지금 규칙 그대로 유지하고, 현재 화면 범위를 사각형으로 표시한다.

### 3.5 충돌 확장 (Task 107 이후)

- 지금: 산맥과 경계만 막는다. 탑다운 화면에서는 광맥과 건물 위를 걸어 지나가는 모습이 어색할 수 있다.
- 계획: 광맥, 거점, 제작소에 작은 발자국(예: 반지름 0.35단위)을 주고 `isWorldPointWalkable` 옆에 `isWorldPointBlocked`를 둔다. 이동 판정만 바뀌고 저장 값은 그대로다.
- 이미 안에 서 있으면 막지 않는 규칙을 그대로 적용한다(저장된 위치 보호).
- 광맥이 길을 막아 갇히는 배치가 생기지 않는지 월드 생성 결과로 검사한다(광맥 간격은 이미 2단위 이상).
- **구현(Task 107, 111):** 반지름 대신 발밑 상자(`WORLD_OBSTACLE_BOXES`, `SCENERY_BLOCK_BOXES`)와 플레이어 발 상자(`PLAYER_FOOT` 0.18 × 0.12)로 했고, 판정은 `worldObstacles`·`playerCanStand`, 이동은 `worldStepFoot`이다(`js/player.js`). 도달 가능성은 생성 월드 25개와 고정 저장 파일, 산 너머 채우기 검사로 테스트한다.

### 3.6 상호작용

- 가까운 대상: 플레이어에서 일정 거리(예: 1단위) 안의 광맥, 공방, 제작소, 앞으로의 마을 시설.
- PC: 상호작용 키(예: E 또는 Space). 모바일: 화면 오른쪽 아래 버튼.
- 광맥: 미확보면 확보(`secureMine`), 확보면 채굴(`mineMine`). 공방: 패널 열기.
- 기존 패널 버튼(원격 확보·채굴)은 유지한다. 없앨지는 사용자 결정(청사진 24.4 #1).

### 3.7 화면 구성 (월드 중심)

- 월드 캔버스가 화면 전체를 채운다.
- 위쪽 작은 HUD: 골드, 가챠권, 명성, 다음 할 일 한 줄.
- 기존 탭(채굴, 개발, 인부, 연구, 납품)과 기록은 여닫는 패널로 옮긴다. 내용과 기능은 그대로이며 `ui.js`의 기존 함수를 그대로 쓴다.
- 모바일: 왼쪽 아래 가상 조이스틱, 오른쪽 아래 상호작용 버튼, 패널은 아래에서 올라오는 시트.

### 3.8 렌더러 전환 방식

- 전환 중에는 두 렌더러가 함께 있다. 선택은 URL(`?view=topdown` / `?view=classic`) 또는 별도 localStorage 키로 하며, 게임 저장 데이터에는 넣지 않는다.
- 탑다운이 2.5D의 기능(지형, 광맥, 발견 표시, 지도, 선택 정보, 플레이어)을 모두 갖추고 화면 확인을 통과하면 기본값을 탑다운으로 바꾼다.
- 그 뒤 2.5D 코드를 제거한다. 제거 전에 2.5D 전용 회귀 테스트를 탑다운 동등 테스트로 바꾼다.

## 5. 회귀 안전장치 (Task 103)

전환 중에 기존 기능이 깨지지 않도록 `tests/chunks/04.js`에 다음을 고정했다.

- 고정 저장 파일(`tests/fixtures/save_v1_midgame.json`, 현재 코드로 만든 중반 진행 저장)을 불러와 모든 핵심 값이 그대로인지, 다시 저장하면 같은 구조인지 확인.
- 2.5D 월드 무대가 페이지에 없어도 로직(확보, 채굴, 이동, 발견, 터널, 저장)이 동작하는지 확인(렌더러 교체 안전장치).
- 플레이어 위치 불변식: 월드를 무작위로 오래 걸어도 걸을 수 없는 곳에 들어가지 않음, 터널이 닫혀 있으면 산 너머로 못 감, 열리면 갈 수 있음, 이동 속도.
- 채굴·제작·경제의 정확한 수치, 광맥 상태 전이, 터널 공사 흐름.
- 저장에 렌더러 상태가 섞이지 않음(저장 키 목록 고정).

탑다운 Task에서는 이 테스트가 계속 통과해야 하며, 화면 동작은 Chromium 확인으로 따로 검증한다.
